Context

The canonical failure depends on controlled retrieval of current and deprecated refund policies. TRACE needs a small, pinned corpus with stable provenance before the runner and verifier can produce meaningful evidence.

Objective

Build the Month 1 policy corpus and controlled retrieval layer, including search_docs.

Scope

Include current refund policy, deprecated refund policy, resolved incident document, stable document and section IDs, status metadata, controlled ranking, and retrieval logs.

Deliverables

Pinned policy document corpus.

Retrieval chunk schema with provenance.

search_docs tool implementation.

Configurable retrieval ordering for tests.

Retrieval event data needed by trace logging.

Acceptance Criteria

Current, deprecated, and resolved documents are distinguishable.

Retrieval order can be controlled for tests.

Every returned chunk includes provenance.

Retrieved docs are traceable to the corpus.

No silent truncation.

Suggested Technical Approach

Start with deterministic keyword/BM25 or lightweight local fixtures. Do not add a hosted vector database unless the experiment requires it; FAISS, Chroma, or SQLite-backed fixtures are optional only if they materially help.
